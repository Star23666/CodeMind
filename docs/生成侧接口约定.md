# CodeMind 生成侧接口约定

本文档描述 RAG 生成侧与检索侧、历史服务、知识地图和 AI 出题 LLM 能力之间的当前约定。实现基线：Issue #18 多知识库 AI 出题，更新时间 2026-07-17。

## 1. RAG 生成侧职责

`POST /api/chat` 的完整链路为：

```text
JWT 用户与公共/私人知识库可读权限校验
→ 检索侧返回 rewritten_question、sources 和空结果原因
→ 生成侧组装受长度限制的 RAG Prompt
→ 调用在线 LLM 或本地演示回答
→ 校验和清理来源编号
→ 在同一事务保存问答记录与来源快照
→ 返回 ChatResponse
```

生成侧不负责上传、解析、切分、Embedding 入库和 Chroma 查询实现，但依赖检索侧提供结构稳定、用户隔离正确的来源数据。

## 2. HTTP 契约

请求需要 JWT：

```http
POST /api/chat
Authorization: Bearer <access_token>
Content-Type: application/json
```

```json
{
  "knowledge_base_id": 42,
  "question": "操作系统中的进程和线程有什么区别？",
  "top_k": 4,
  "score_threshold": 0.45,
  "rerank_top_n": 2,
  "enable_rewrite": true,
  "enable_rerank": true
}
```

响应：

```json
{
  "qa_record_id": 1001,
  "knowledge_base_id": 42,
  "question": "操作系统中的进程和线程有什么区别？",
  "rewritten_question": "操作系统中进程与线程的区别是什么？",
  "answer": "进程拥有独立地址空间，线程共享进程资源。[来源1]",
  "sources": [
    {
      "document_id": 1,
      "chunk_id": 10,
      "file_name": "操作系统笔记.pdf",
      "chunk_index": 3,
      "page_no": 12,
      "score": 0.864321,
      "source_text": "进程拥有独立地址空间，线程共享进程资源……",
      "jump_url": "/documents/1/chunks/10"
    }
  ]
}
```

临时 `X-User-Id` 已废弃，调用方不得再发送或依赖该请求头。

## 3. 检索侧契约

实现位置：`backend/app/services/retrieval_service.py`。

```python
async def retrieve_for_chat(request: ChatRequest, user_id: int) -> RetrievalResult:
    ...
```

`RetrievalResult` 至少提供：

- `rewritten_question: str | None`
- `sources: list[SourceReference]`
- `empty_message: str | None`

`SourceReference` 字段：

| 字段 | 约定 |
| --- | --- |
| `document_id` | MySQL `documents.id` |
| `chunk_id` | MySQL `document_chunks.id` |
| `file_name` | 用户可识别的来源文件名 |
| `chunk_index` | 文档内从 0 开始的片段序号 |
| `page_no` | 页码或 `null` |
| `score` | 相似度或 rerank 分数 |
| `source_text` | 进入 Prompt 并写入历史的文本快照 |
| `jump_url` | `/documents/{document_id}/chunks/{chunk_id}` |

`knowledge_base_id` 必须来自 `/api/knowledge-bases`，不能假设公共库 ID 为 `1`。私人库检索必须同时按
`owner_id` 和 `knowledge_base_id` 隔离；公共库检索只按动态取得的 `knowledge_base_id` 限定，从而召回
该公共库内所有上传者的资料。Embedding 服务、Chroma 或模型重写不可用时，应抛出带 HTTP 状态语义的
`RetrievalServiceError`，不能返回伪造向量或伪造来源。

## 4. Prompt 与回答规则

实现位置：`backend/app/services/prompt_builder.py`。

- 来源按 `[来源1]`、`[来源2]` 编号。
- 单条来源和总上下文都有字符预算，避免 Prompt 无限制增长。
- 文档片段属于不可信数据，Prompt 明确禁止执行片段内指令。
- 模型只能根据提供的资料回答；依据不足时必须明确说明。
- 输出后清理不存在、残缺或超出范围的来源编号。
- 模型未主动给出引用时，系统追加有效参考资料列表。
- 重复尾部和不完整引用会在返回前清理。

## 5. LLM 错误与降级

实现位置：`backend/app/services/llm_client.py`。

| 场景 | 当前行为 |
| --- | --- |
| 未配置 `LLM_API_KEY` 或 `LLM_MODEL` | 普通 RAG 返回基于检索片段的本地演示回答 |
| API Key 无效 | 转换为明确的 502 错误 |
| 限流、网络或超时 | 返回 503 语义的可重试错误 |
| 服务端异常或空回答 | 返回 502 |
| Qwen3.5/Qwen3.6 未配置思考开关 | 普通 RAG 自动使用非思考模式 |
| 思考耗尽额度且尚无正文 | 自动关闭思考重试一次 |
| 结构化导图输出达到长度上限 | 在总超时内提高任务级额度重试一次 |
| 知识地图流持续输出但超过墙钟总时限 | 取消流、释放全局并发槽位并返回 504 |
| 非流式回答超过硬生成时限 | 终止请求并返回 504 |

可配置项：

```dotenv
LLM_TIMEOUT_SECONDS=45
LLM_MAX_RETRIES=1
LLM_MAX_TOKENS=1200
# LLM_ENABLE_THINKING=false
LLM_THINKING_BUDGET=512
CHAT_TOTAL_TIMEOUT_SECONDS=60

MIND_MAP_TIMEOUT_SECONDS=600
MIND_MAP_TOTAL_TIMEOUT_SECONDS=900
MIND_MAP_ENABLE_THINKING=false
MIND_MAP_BATCH_MAX_TOKENS=1600
MIND_MAP_MERGE_MAX_TOKENS=4096
MIND_MAP_RETRY_MAX_TOKENS=6400

QUIZ_TIMEOUT_SECONDS=300
QUIZ_MAX_TOKENS=12000
QUIZ_STRUCTURE_MAX_RETRIES=1
QUIZ_ENABLE_THINKING=false
QUIZ_CONTEXT_MAX_TOKENS=8000
```

知识地图和 AI 出题不使用普通 RAG 的本地演示降级；缺少在线 LLM 配置时直接返回 `503`。

生成链路日志记录检索模型与耗时、LLM 模型、首 Token、总耗时和 `finish_reason`，用于区分检索慢、首 Token 慢和输出被截断。日志不得输出 API Key 或完整 Prompt。

## 6. 问答历史契约

实现位置：`backend/app/services/qa_history_service.py`。

- `qa_records` 与 `qa_sources` 在同一事务写入，任一来源失败时整体回滚。
- 保存文件名、片段序号、页码、分数和 `source_text` 快照。
- 删除文档时，`qa_sources.document_id` 和 `chunk_id` 置空，快照继续保留。
- 历史详情中的失效来源 `jump_url=null`，前端不应再提供原文跳转。
- `GET /api/qa-records` 按当前 JWT 用户查询列表，可按知识库过滤。
- `GET /api/qa-records/{id}` 返回完整来源快照，并校验用户归属。
- `POST /api/qa-records/{id}/feedback` 校验同一归属后持久化评分；重复提交返回 `409`。
- 管理员可按评分、用户和知识库查询真实反馈数据；私人库的问题、回答、来源和知识库名称不会随反馈接口返回。

## 7. 知识地图 LLM 边界

知识地图也使用 `LlmClient`，但由 `mind_map_service.py` 单独组织结构化 Prompt：

```text
读取已完成解析的片段
→ 采样并按每 3 条片段分批提炼
→ 合并为层次化 JSON
→ 校验节点、深度、数量和真实来源编号
→ 保存历史版本
```

当前结构约定：

- 节点类型为 `overview`、`chapter`、`concept` 或 `detail`。
- `key_points` 最多 3 条，`learning_tip` 为具体学习动作。
- 非根节点优先绑定真实来源；未知 `chunk_id` 被丢弃。
- 私人地图只读取当前用户的片段；公共地图、节点追问和扩展可读取同一公共库中不同上传者的片段。
- 生成、节点提问和节点扩展共享服务级并发限制 3。
- 每次模型调用默认受 `MIND_MAP_TOTAL_TIMEOUT_SECONDS` 墙钟总时限保护；即使上游持续零星输出，达到时限也会取消并释放并发槽位。
- 某一批失败时取消未完成请求，避免失败后继续消耗 API。
- 批次提炼限制主题和字段长度；合并阶段优先保证 JSON 完整闭合。
- 合并输出使用独立 token 预算，长度耗尽时可在同一次总超时内自动提高额度重试一次，重试不会重新计算 900 秒。
- 管理员可显式设置 `MIND_MAP_TOTAL_TIMEOUT_SECONDS=0` 关闭保护，但异常流可能永久占用全部 3 个槽位，生产环境不建议使用。
- 后台任务记录阶段、进度、结果和错误；前端通过轮询恢复任务。
- 节点学习字段保存在 `mind_map_histories.result_json`，无需新增数据库列，旧 JSON 通过默认值兼容。

相关接口：

| 接口 | 用途 |
| --- | --- |
| `POST /api/mind-maps/jobs` | 创建后台生成任务 |
| `GET /api/mind-maps/jobs/{job_id}` | 查询进度和结果 |
| `POST /api/mind-maps/ask` | 使用节点来源回答问题 |
| `POST /api/mind-maps/expand` | 使用节点来源扩展子结构 |
| `/api/mind-maps/histories` | 管理历史版本 |

## 8. AI 出题 LLM 边界

AI 出题由 `quiz_service.py` 组织结构化 Prompt，并复用 `LlmClient`：

```text
校验 1～5 个知识库读取权限和内容量
→ 后台任务执行前再次校验权限
→ 在知识库内部按文档轮询，再跨知识库轮询，并限制片段、字符和 Token 预算
→ 解析一次当前用户 LLM 运行时
→ 请求严格 JSON，有限重试沿用同一运行时
→ Pydantic 校验整批题型、答案、认知层级、文档覆盖、来源和数量
→ 全部有效后在事务中保存临时题目
```

- 文档片段作为不可信 JSON 数据放入 Prompt，其中的命令和角色设定不得改变出题协议。
- 每道题至少引用一个本次上下文中存在的 `source_id`，未知来源使整批输出失效。
- 未限定主题时，整套题必须覆盖上下文中可用的多份文档；进阶和挑战练习还会校验应用、分析题所占比例。
- 模型返回无效 JSON、错误选项、错误答案类型、重复题干或数量不符时不保存任何题目。
- 个人模型启用时，首次生成和结构重试使用同一个 `runtime_config`，调用失败直接报告，不切换系统模型。
- 没有个人模型时使用 `.env` 系统模型；Embedding 仍是系统统一配置。
- 获取题目接口使用单独的公开响应模型，不含答案、解析和来源正文。
- 提交后才评分并返回答案；提交结果返回前先组装数据，随后删除临时会话及其题目。

## 9. 当前实现状态

已完成：

- RAG 有来源、无来源、检索异常和 LLM 异常闭环。
- 公共库跨用户检索、问答、来源跳转和知识地图作用域。
- 来源编号校验、Prompt 注入防护和上下文预算。
- 问答历史事务保存和删除原文后的来源快照。
- 问答历史前端列表、详情和原文可用性展示。
- 用户反馈持久化、重复保护、只读回显、管理员筛选页面和私人上下文脱敏。
- 知识地图异步生成、历史、追问、扩展和学习节点结构。
- 多知识库 AI 出题、六类结构校验、评分、来源、BYOK 路由和临时数据清理。

仍需完善：

- 基于真实在线模型的固定测试集和语义质量评估；结构校验通过不等于题目事实必然正确。
- 模型耗时、首 Token、Token 消耗和错误率的持续记录，重点关注大资料多题生成的长等待问题。
- 将真实 MySQL、Chroma 和在线模型回归整理为可选 smoke 测试。

跨模块问题、优先级和当前实测证据统一见 [已知问题与后续计划](已知问题与后续计划.md)。
