# CodeMind 前端视觉样式规范

## 1. 设计定位

CodeMind 是以“知识可信、答案有据”为核心的 AI 知识产品。视觉上应当保持安静、清晰、轻盈，避免传统管理后台的大面积实色卡片、密集描边和过多状态标签。

首页采用“编辑感衬线标题 + 现代无衬线交互控件”的组合：

- 内容气质：可靠、克制、具有知识感。
- 交互气质：轻量、即时、接近现代 AI 工作台。
- 品牌识别：保留 CodeMind 艺术字 Logo，以蓝色为唯一主强调色。
- 页面层级：优先通过留白、字号和透明度建立层级，阴影仅用于悬浮层和核心输入区域。

## 2. 色彩系统

### 基础色

| 用途 | 推荐值 |
| --- | --- |
| 页面底色 | `#F8FBFF` |
| 浅蓝过渡 | `#EDF6FF` |
| 主标题 | `#11213A` |
| 正文 | `#28394F` |
| 次级文字 | `#627187` |
| 弱提示 | `#8997AA` |
| 主蓝色 | `#2465D4` |
| 亮蓝色 | `#238FE8` |
| 浅蓝背景 | `#EEF6FF` |
| 半透明边框 | `rgba(149, 181, 219, 0.62)` |

### 使用规则

- 一个视图中只保留一个高饱和主色，默认使用蓝色。
- 禁止用多种渐变分别装饰不同卡片。
- 错误、成功、警告色仅用于真实状态反馈，不作装饰。
- 玻璃质感使用半透明白色、细边框和轻微模糊，不使用高强度霓虹效果。

## 3. 字体与排版

### 展示标题

```css
font-family: "Source Han Serif SC", "Songti SC", "STSong", serif;
```

用于首页主标题、AI 回答标题、知识地图章节标题。中文优先使用思源宋体或系统宋体，形成接近 Claude/编辑出版物的知识感。

### 界面正文

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
```

用于导航、输入框、按钮、表单和正文，保证小字号可读性。

### 数字与状态

```css
font-family: "DIN Alternate", Consolas, monospace;
```

用于 Top K、置信度、进度和技术状态。不要用于大段文字。

### 字号建议

- 首页主标题：`46px–76px`
- 页面标题：`32px–48px`
- 模块标题：`20px–28px`
- 正文：`15px–17px`
- 辅助文字：`11px–13px`

## 4. 圆角、描边与阴影

- 首页核心输入框：`26px`
- 大型结果容器：`24px`
- 普通内容卡片：`16px–18px`
- 小按钮与标签：`10px–12px`
- 胶囊按钮：`999px`

描边应使用低对比度蓝灰色。核心浮层推荐阴影：

```css
box-shadow:
  0 28px 80px rgba(48, 107, 175, 0.16),
  0 8px 24px rgba(72, 124, 184, 0.08);
```

不要为页面上的每一个模块添加阴影。

## 5. 首页布局

### 初始状态

1. 顶部为半透明导航条，左侧保留 CodeMind Logo。
2. 中央为简短标题、单段说明和一个一体化提问框。
3. 知识库、Top K、置信度位于输入框底部工具栏。
4. 发送按钮使用圆形向上箭头，不重复显示“发送问题”文字。
5. 初始状态不挂载空回答、空来源和空评价区域。

### 回答状态

1. 原标题和提问框向上淡出。
2. 当前问题、回答、来源和评价从下方进入。
3. 流式生成时先展示回答骨架和状态。
4. 回答完成后允许用户通过“继续提问”返回输入状态。
5. 页面背景独立于内容状态，切换时保持连续。

## 6. 动效规范

### 页面转场

- 离场时间：约 `340ms`
- 入场时间：约 `550ms`
- 离场：`translateY(-64px) + opacity`
- 入场：`translateY(72px) + opacity`
- 推荐缓动：`cubic-bezier(0.22, 1, 0.36, 1)`

### 导航悬浮

- 所有业务页面共用同一套半透明白色导航。
- 桌面菜单项间距保持在 `20px–30px`，不使用拥挤的胶囊菜单。
- 下划线从左向右展开。
- 时长约 `280ms`。
- 当前路由持续显示下划线。
- 不使用整块高亮胶囊作为导航激活态。
- 产品当前固定为浅色视觉，导航不提供深色模式开关。

### 粒子背景

- 首页背景使用覆盖视口的 WebGL Canvas，以片元着色器生成蓝白波浪。
- 不在背景上绘制独立漂浮圆点；粗颗粒必须参与蓝色色带的颜色计算，成为波浪自身的材质。
- 波浪边界由多层流动噪声与正弦曲线共同扭曲，运动表现为整条蓝白边界推进、弯曲和回落。
- 着色器使用圆周时间偏移构成 `12s` 首尾一致循环，避免固定区域内往返或循环跳帧。
- 波浪主体使用至少六级重叠色阶，边界不得呈现为清晰分层。
- 最深蓝表现为中间的窄幅柔和脊线，脊线下方重新过渡到较亮的蓝青色，不能让最深蓝铺满底部。
- 浅青色可沿独立曲线局部压入蓝色区域，形成间歇出现、柔和弯曲的细带。
- 动画周期约 `20s`。时间参数保持单调递增，所有周期函数使用整数相位倍数，禁止在循环末尾显式重置时间。
- 蓝白混合区应保持较长的纵向过渡。
- Canvas 渲染分辨率最高使用 `1.5× DPR`；WebGL 不可用时降级为静态蓝白渐变。
- 渐变光斑由 CSS 承担，中央标题区域始终保留浅色空间。
- 页面不可见时暂停动画。
- `prefers-reduced-motion: reduce` 时显示静态背景。

## 7. 组件策略

- Element Plus 继续承担弹窗、菜单、表格、上传、分页等功能组件。
- 首页品牌化区域优先使用 Vue、原生 HTML 和 CSS。
- 可复用 Element Plus 的行为能力，但应弱化其默认边框、背景和按钮外观。
- 不为了单个动效引入大型动画库。
- 不在当前项目中同时引入另一套完整成品 UI 组件库。

## 8. 响应式与无障碍

- 桌面内容最大宽度根据功能控制在 `880px–1080px`。
- 移动端左右安全边距至少 `12px`。
- 所有图标按钮必须提供 `aria-label` 或 `title`。
- 下拉菜单、弹窗和滑块应保留键盘操作能力。
- 颜色不能作为唯一状态提示。
- 所有动画都必须兼容系统“减少动态效果”设置。

## 9. 当前首页相关文件

- `frontend/src/views/HomeView.vue`：首页背景、标题与数据加载。
- `frontend/src/components/home/HomeParticleBackground.vue`：粒子和渐变背景。
- `frontend/src/components/layout/AppHeader.vue`：全站统一的玻璃导航、间距与下划线动效。
- `frontend/src/components/chat/ChatPanel.vue`：提问框、参数菜单和页面转场。
- `frontend/src/components/chat/AnswerCard.vue`：回答、来源和评价的视觉容器。

后续修改首页时，应优先调整以上文件，并保持其他业务页面的现有结构不受影响。
